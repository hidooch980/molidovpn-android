# MolidoVPN 4.0.5 — release notes

## Included in this release candidate

- Server catalog refresh policy updated to a five-minute foreground/live-sync cadence, with ETag checks and last-known-good validation.
- Simplified connection home and a consolidated navigation drawer.
- Molido Agent Hub coordinates server discovery, network policy and remote app configuration with persisted dispatch checkpoints and network safety gates.
- CI self-healing diagnoses failed validation runs, retries transient failures once and opens a sanitized diagnostic issue for deterministic or repeated failures.
- Weekly safe maintenance is limited to agent-owned Python diagnostic files; changes are proposed for review and are never auto-merged.
- Transport compatibility inventory covers MTProto Proxy, Tor, TCP, UDP, QUIC, WebSocket, gRPC, XHTTP, HTTP/2, HTTP/3, HTTPUpgrade and mKCP.
- Benchmark report gate requires two network profiles, repeated samples, stability soak and security checks before a transport can be considered for manual review.
- Removed duplicate Rust dependency-install and core-test steps from Android validation.

## Important compatibility notes

- Existing Tor, TCP/UDP, QUIC/MASQUE, WebSocket, gRPC, XHTTP, HTTPUpgrade and HTTP/3 client paths are documented from source. Documentation does not imply that every server or carrier has passed end-to-end tests.
- HTTP/2 MASQUE remains experimental because gateway interoperability is limited.
- Modern unmasked mKCP parsing and Xray `kcpSettings` generation are included, but remain non-selectable pending live-server/device tests. Legacy mKCP header/seed masks are not yet supported.
- MTProto Proxy was not found as a client adapter and remains unavailable; it is a Telegram-specific proxy, not a full-device VPN transport.
- No transport is enabled merely because it appears in the catalog. New or unvalidated paths remain disabled until compatible client/server and real-device tests pass.

## Release verification

This is a release-candidate change log. A public installable release is complete only after Android CI passes, the existing signing certificate is verified against published Molido releases, signed APKs are built for phone and TV targets, and the GitHub release assets and checksums are published.
