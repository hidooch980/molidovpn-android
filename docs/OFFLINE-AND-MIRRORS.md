# آمادگی برای اینترنت ملی: کانفیگ‌های پشتیبان، ارسال برنامه و آینه‌ها

## ۱. کانفیگ‌های پشتیبان آفلاین (بدون نیاز به سرور)

- **حافظهٔ کانفیگ‌های سالم:** هر سرور V2Ray که روی همین گوشی واقعاً کار کرده (در اتصال یا اسکن پس‌زمینه)،
  ذخیره می‌شود: تا ۲۴ سرور، جدیدترین‌ها اول، و بعد از ۲۱ روز پاک می‌شوند. فایل با کلید Android Keystore
  رمزنگاری می‌شود (`known-good.bin`) و بیرون از همان گوشی به درد نمی‌خورد.
- این سرورها همیشه به فهرست V2Ray اضافه می‌شوند. اگر هیچ فهرستی گرفته نشود (گیت‌هاب، Worker و
  آینه‌ها همه بسته)، حالت «خودکار» و V2Ray با همین حافظه و **مجموعهٔ اضطراری** کار می‌کنند.
- **مجموعهٔ اضطراری:** فایل `app/src/main/assets/emergency-configs.txt` موقع ساخت هر نسخه با
  `tools/refresh-emergency-configs.py` از بهترین سرورهای همان روز (لینک `/sub/1` که Worker بر اساس گزارش‌های
  ایران مرتب می‌کند) پر می‌شود. سرورهای VIP خودتان به‌صورت پیش‌فرض داخلش **نمی‌روند**، چون هر کسی می‌تواند APK
  را باز کند و سروری که داخل APK رفت دیگر پس گرفته نمی‌شود. برای گذاشتن آن‌ها: `EMERGENCY_INCLUDE_VIP=1`.

## ۲. ارسال خود برنامه (بدون اینترنت)

در صفحهٔ «به دوستانت بگو» دکمهٔ **ارسال فایل برنامه** هست: خود فایل APK نصب‌شده را از راه بلوتوث،
Nearby Share یا هر پیام‌رسانی (بله، روبیکا، ایتا) می‌فرستد. گیرنده باید «نصب از منابع ناشناس» را اجازه دهد.

## ۳. آینه برای به‌روزرسانی و لینک اشتراک

برنامه به این ترتیب امتحان می‌کند و با اولین موفق کار می‌کند:

1. Worker کلادفلر (`molido-sub.hidooch980.workers.dev/app/latest.json`)
2. API گیت‌هاب
3. آینه‌های داخل `remote/resilience.json` ← `mirrors.update` (به همان ترتیب)

لینک اشتراک V2Ray: پنج لینک Worker ← `/ios` ← raw گیت‌هاب ← jsDelivr ← `mirrors.sub`.

**امنیت:** به آینه اعتماد نمی‌شود. APK دانلودشده باید (۱) با SHA-256 داخل اطلاعات نسخه یکی باشد (اگر
اطلاعات نسخه آن را داشته باشد؛ گیت‌هاب `digest` را می‌دهد) و (۲) **همیشه** با همان کلید امضای برنامهٔ نصب‌شده
امضا شده باشد. اگر یکی نخواند، فایل پاک می‌شود و منبع بعدی امتحان می‌شود.

### ساختار یک آینه

یک پوشهٔ عمومی با HTTPS که این فایل‌ها را دارد (`tools/mirror-upload.sh` در مخزن اصلی همین را می‌سازد):

```
<آینه>/latest.json                       ← هم‌شکل API گیت‌هاب + sha256 هر فایل
<آینه>/MolidoVPN-android-arm64.apk
<آینه>/MolidoVPN-android-armv7.apk
<آینه>/MolidoVPN-android-universal.apk
<آینه>/remote/resilience.json            ← تا تنظیمات هم از آینه برسد
<آینه>/sub.txt                           ← کپی لینک اشتراک
```

آدرس پوشه را (بدون `/` آخر) در `mirrors.update`، و آدرس کامل `sub.txt` را در `mirrors.sub` بگذارید.

### کدام گزینه‌ها بدون VPS کار می‌کنند؟ (بررسی ۲۶ مهر ۱۴۰۵، از سرور خارج از ایران)

| گزینه | برای APK (۶۰ تا ۱۱۰ مگ) | برای فایل‌های کوچک (json، sub) | هزینه | نکته |
|---|---|---|---|---|
| Worker فعلی (`/app/…`) | ✅ همین الان کار می‌کند (کش لبهٔ کلادفلر) | ✅ | رایگان | `workers.dev` در ایران گاهی فیلتر است |
| همان Worker روی یک دامنهٔ شخصی | ✅ | ✅ | فقط هزینهٔ دامنه | بهترین گزینهٔ بدون VPS: در Cloudflare ‏Workers ← Settings ← Domains & Routes یک Custom Domain اضافه کنید و آدرسش را با `/app` در `mirrors.update` بگذارید |
| jsDelivr | ❌ سقف ۲۰ مگابایت برای هر فایل | ✅ تست شد (۲۰۰) | رایگان | الان برای policy و لینک اشتراک استفاده می‌شود |
| raw.githubusercontent | ❌ (APK داخل مخزن نمی‌رود) | ✅ تست شد | رایگان | در ایران گاهی کند/فیلتر |
| statically.io | ❌ | ❌ تست شد: به http هدایت می‌کند و جواب نمی‌دهد | — | استفاده نشد |
| GitHub Pages | ⚠️ فایل تا ۱۰۰ مگ؛ ولی APK باید در مخزن کامیت شود | ✅ | رایگان | `github.io` در ایران معمولاً فیلتر است |
| Cloudflare R2 | ✅ (۱۰ گیگ رایگان، ترافیک خروجی رایگان) | ✅ | رایگان در سقف | برای فعال کردن، کلادفلر **کارت بانکی بین‌المللی** می‌خواهد |
| Cloudflare Pages | ❌ سقف ۲۵ مگابایت برای هر فایل | ✅ | رایگان | |
| فضای ابری داخلی (مثل آروان) | ✅ | ✅ | پولی (ریالی، ارزان) | تنها گزینه‌ای که در قطعی کامل اینترنت بین‌الملل هم در دسترس می‌ماند؛ حساب ایرانی لازم است |

### آپلود خودکار به آینهٔ S3 (آروان یا R2)

مرحلهٔ «Mirror upload» در گردش‌کار انتشار مخزن اصلی فقط وقتی اجرا می‌شود که این Secretها در
GitHub ‏(Settings ← Secrets and variables ← Actions) وجود داشته باشند؛ در غیر این صورت بی‌صدا رد می‌شود:

| Secret | مثال |
|---|---|
| `MIRROR_S3_ENDPOINT` | `https://s3.ir-thr-at1.arvanstorage.ir` یا `https://<account>.r2.cloudflarestorage.com` |
| `MIRROR_S3_BUCKET` | `molido` |
| `MIRROR_S3_ACCESS_KEY` / `MIRROR_S3_SECRET_KEY` | کلیدهای دسترسی باکت |
| `MIRROR_PUBLIC_URL` | آدرس عمومی همان باکت، مثلاً `https://molido.s3.ir-thr-at1.arvanstorage.ir` |

باکت باید «عمومی» (Public read) باشد. بعد از اولین آپلود، `MIRROR_PUBLIC_URL` را در `mirrors.update`
و `MIRROR_PUBLIC_URL/sub.txt` را در `mirrors.sub` فایل `remote/resilience.json` بگذارید.
